# 방 프리팹 JSON 작성법

`maps/prefabs/`에 프리팹 하나당 JSON 파일 하나를 둔다. 방 크기는 서로 달라도 된다. 타일 좌표는 왼쪽 위가 `[0, 0]`이고, 오른쪽으로 X, 아래로 Y가 커진다. 현재 타일은 한 칸이 16×16px이다.

## 파일 예제

다음은 왼쪽과 오른쪽 끝이 열려 있는 작은 복도다. 사용할 때는 한쪽을 방에 맞춰 붙이고 반대쪽에 다른 방을 붙인다. 방 프리팹은 같은 형식에서 `kind`를 `room`으로 바꾸고 벽과 발판을 원하는 모양으로 그리면 된다.

```json
{
  "id": "hall_example",
  "kind": "corridor",
  "size": [4, 5],
  "terrain": [
    [0, 0, "grass"], [1, 0, "grass"], [2, 0, "grass"], [3, 0, "grass"],
    [0, 4, "grass"], [1, 4, "grass"], [2, 4, "grass"], [3, 4, "grass"]
  ],
  "decoration": [[1, 3, "grass_deco.tuft"]],
  "exits": [
    {
      "side": "left", "offset": 1, "span": 3,
      "cap": {
        "terrain": [[0, 1, "grass"], [0, 2, "grass"], [0, 3, "grass"]],
        "decoration": [[1, 3, "grass_deco.reeds"]]
      }
    },
    {
      "side": "right", "offset": 1, "span": 3,
      "cap": {
        "terrain": [[3, 1, "grass"], [3, 2, "grass"], [3, 3, "grass"]]
      }
    }
  ]
}
```

| 필드 | 작성 규칙 |
| --- | --- |
| `id` | 카탈로그 전체에서 고유한 문자열 |
| `kind` | `room` 또는 `corridor` |
| `size` | `[가로, 세로]` 타일 수 |
| `role` | 방의 역할. `start`, `normal`, `goal` 중 하나이며 생략하면 `normal` |
| `spawn` | `start`, `goal` 방에 필요한 `[x, y]`. 시작 방에서는 플레이어 위치, 목표 방에서는 목표 표식 위치. 일반 방에 지정하면 전용 방이 없는 경우 시작이나 목표로 쓸 수 있음 |
| `terrain`, `decoration` | `[x, y, 타일 이름]` 목록. 목록에 없는 칸은 비어 있음 |
| `exits` | 출입구 목록. 방에는 하나 이상, 복도에는 두 개 이상을 지정 |

## 지형 타일과 장식 타일

`maps/tiles.json`은 프리팹 JSON에서 사용할 이름을 등록하는 곳이다. 지형 이름과 장식의 아틀라스 좌표를 같은 파일에 둔다.

```json
{
  "grass": { "terrain": "grass" },
  "stone": { "terrain": "stone" },
  "grass_deco.tuft": [1, 0, 0]
}
```

- **자동 지형**은 Godot의 `dream_tileset.tres`에 지형을 만들고, 위처럼 실제 지형 이름을 팔레트에 한 번 등록한다. 예제의 `stone`은 TileSet에 해당 지형을 만든 뒤 추가하는 항목이다. 이후 방, 복도, 샤프트, 출입구 마감에서 `[x, y, "stone"]`처럼 사용할 수 있다.
- 서로 다른 지형 세트에서 이름이 겹치면 `{ "terrain": "stone", "terrain_set": 1 }`처럼 Godot의 0부터 시작하는 세트 번호를 붙인다. 서로 맞닿는 두 재질의 경계 타일이 필요하면 같은 지형 세트에 두고, 두 재질 사이의 조합도 TileSet에 그려 둔다.
- 생성기는 맵 배치와 출입구 마감이 끝난 뒤 각 지형의 연결 규칙을 적용한다. 방 경계와 빈 칸도 포함해 모서리, 벽, 바닥 타일을 고른다. 규칙에 필요한 조합이 없으면 Godot은 가장 가까운 조합을 사용한다. 자동 지형에 쓰이는 타일의 충돌 모양은 TileSet에서 설정한다.
- **고정 타일**은 `[소스 ID, 아틀라스 X, 아틀라스 Y]`로 등록한다. 장식은 이 방식으로 배치하며 지형과 같은 칸에 겹쳐도 충돌하지 않는다. 지형 레이어에도 특정 타일을 고정해야 할 때 아틀라스 형식을 사용할 수 있다.
- 같은 레이어의 같은 칸에 여러 타일을 쓰면 마지막 타일이 적용된다. 마감은 기본 타일 배치 이후에 적용된다.

## 출입구와 배치

- `side`는 `left`, `right`, `up`, `down`이다. `offset`은 좌우 벽에서는 위에서부터, 상하 벽에서는 왼쪽에서부터 센다. `span`은 열린 타일 칸 수다. 위 예제의 좌우 출입구는 모두 Y가 1~3인 칸이다.
- 연결하는 두 문의 방향은 반대여야 한다. 문의 위치나 크기가 다르면 작은 문의 `span`만큼 큰 문에 포개고, 나머지는 마감 타일로 닫는다.
- 큰 문에서 어느 쪽에 붙일지 `align`으로 정한다. 기본값 `"center"`는 가운데에 맞추며 홀수 칸 차이는 시작 쪽으로 한 칸 치우친다. `"start"`는 위쪽 또는 왼쪽, `"end"`는 아래쪽 또는 오른쪽이다. 좌우 벽의 문에서 바닥을 맞추려면 `"end"`가 편하다.
- 기본 `terrain`에서는 출입구 칸을 비워 둔다. `"cap": { "terrain": "grass" }`로 출입구 전체에 같은 마감 타일을 지정하거나, 예제처럼 출입구의 각 칸을 목록으로 지정할 수 있다. 완전히 막힌 문에는 선택적인 `cap.decoration`도 적용된다. 부분 연결은 열린 칸을 비워 두고 나머지 칸에만 마감 지형을 놓는다.
- `corridor`는 문 방향을 자유롭게 조합할 수 있다. 좌우 직선, 상하 샤프트, ㄱ자, T자, 십자형 모두 같은 종류다. 주 경로에서 사용하지 않은 복도의 문에도 가지가 붙을 수 있다. 복도끼리 직접 맞닿을 수 있고, 복도는 방 개수에 포함되지 않는다. 기존 `shaft` 프리팹은 `kind`를 `corridor`로 바꾸면 된다.
- 프리팹의 사각 영역은 서로 겹칠 수 없다. 도약 지점, 착지 발판, 출입구를 실제로 통과할 수 있는지는 프리팹을 만들 때 정한다.
- 카탈로그에는 `normal` 방이 하나 이상 필요하다. `start` 또는 `goal` 전용 방이 없으면, 해당 역할에 `spawn`이 있는 일반 방을 사용한다. 주 경로를 잇고 가지를 낼 만큼 연결 가능한 출입구를 둔다.

## Godot용 리소스 만들기

프로젝트 루트에서 아래 명령을 실행한다. 첫 명령은 새 체크아웃에서 Godot이 이미지와 TileSet을 읽을 수 있게 임포트한다. 이후 JSON만 바꿨다면 두 번째 명령만 실행하면 된다.

```bash
godot --headless --editor --import
godot --headless --script tools/import_prefabs.gd
```

생성된 `maps/prefabs.tres`를 원본 JSON과 함께 커밋한다. 빌드는 이 리소스의 타일 배치를 읽는다. **F5**로 생성 맵을 실행할 수 있다. `main.tscn`의 루트 노드에서 `generation_seed`를 0이 아닌 값으로 설정하면 같은 카탈로그와 설정에서 맵을 재현할 수 있다. 0이면 실행마다 새 시드를 고르고 화면에 표시한다. 주 경로 방 수, 가지 수, 가지 깊이도 같은 노드의 Inspector에서 조정할 수 있다.

## 에디터 미리보기

`main.tscn`을 열고 씬 트리에서 `Main`을 선택한다. 인스펙터의 **Generate Map Preview**를 누르면 실행 없이 2D 뷰에서 맵을 볼 수 있다. **Clear Map Preview**를 누르면 초기화된다. 미리보기는 씬 파일에 저장되지 않는다. 같은 시드를 F5에서 쓰려면 출력 창에 표시된 시드를 `generation_seed`에 입력한다.

플레이 중 카메라는 현재 방의 경계 안에서 움직인다. 방이 기본 화면보다 작으면 확대해서 화면을 방 안에 맞춘다. 복도에서는 기본 배율로 플레이어를 따라간다.
